# ArkText — Modern Protocol Port, Complete Change Record

Branch: `modern-protocol` (local only). Written 2026-07-20.
Companion doc: `STATUS.md` (live gate table + how to run the rig). This file
is the full record of everything done, what changed, and why.

## The goal

Bring BlackTek from a 10.98-only server to one that also speaks the modern
(13.40+) client protocol, proven against a real mehah OTClient Redemption at
**15.25** — login, world render, walking, chat, GM actions — while leaving
the legacy 10.98 wire path byte-for-byte untouched.

## The strict rules this work follows

1. **Match BlackTek's coding style and flow.** Tabs, Allman braces,
   `not`/`and`/`or` keyword operators, typed opcode enums
   (`ServerCode`/`SpecialCode`/`CommonCode`) instead of magic numbers,
   file-scope `using namespace BlackTek::Network`, small header helpers,
   lowercase pragmatic comments, terse imperative commit subjects. New
   concepts only when the port genuinely needs them.
2. **Legacy stays untouched.** Every modern behavior branches on the
   connection's resolved protocol profile; a 10.98 client exercises exactly
   the code it always did. The legacy scripted client re-runs green after
   every change.
3. **Version numbers appear in exactly one place** (`protocolprofile.h`).
   Packet code tests feature bits or the transport generation, never raw
   version numbers.
4. **Wire truth comes from the client.** Layouts were derived from mehah's
   own parsers and canary's writers, then validated with byte captures from
   a live 15.25 client. Where the client's belief about an item matters
   (count bytes, tiers, podiums), the server consults the client's own
   appearance flags, never `ItemType`.

## What was done, phase by phase

### Phase H — verification harness (commit `d101782`)
**Why:** nothing else can be trusted without an independent way to check
bytes. **What:** `harness/` Python tooling — `packet_diff.py` (decrypts,
splits, annotates and diffs captures of either framing generation),
`legacy_client.py` / `modern_client.py` (scripted logins that walk and
report), fixture generators — plus a `blacktek_tests` premake target whose
golden byte vectors are generated in Python so the C++ can never bless
itself.

### Phase 0 — profiles + modern transport (commit `7b68139`)
**Why:** the two client generations frame everything differently.
**What:** `src/protocolprofile.h` — the profile registry (10.98 / 13.40 /
14.12 / 15.25) with feature bits and data-driven login layouts. Transport
gained sequence checksums, the padding-byte XTEA layout, block-count outer
lengths and raw-deflate compression (`protocol.cpp`, `outputmessage.h`,
`connection.cpp`). The server-first challenge is framed per generation, so
the modern protocol gets its own port (`game_port_modern`, default 7183 in
`server.toml`) served by `ProtocolGameModern` — a thin subclass tag; modern
clients learn the port from the login webservice, so no byte sniffing.

### Phase A — session-key login (commit `7db0399`)
**Why:** modern clients authenticate through an HTTP login service, not the
old account/password game packet. **What:** `IOLoginData::
sessionKeyAuthentication` (SHA-256 lookup in a new `account_sessions`
table, migration in `data/migrations/`), `onRecvFirstMessage` rewritten
layout-driven so both generations share the credential/ban tail, and
`docker-compose.yaml` gained the opentibiabr login-server service. Verified
against the real Go login-server, unmodified.

### Phase B — asset/id pipeline (commit `ceca7e7`)
**Why:** the server's item ids must translate to what a modern client can
render. **Ground truth found:** CipSoft appearance ids are append-only, so
the classic 10.98 OTB server→client table IS the modern mapping.
**What:** canary's `appearances.proto` vendored (`src/protobuf/`), protoc
wired into premake, `src/appearances.{h,cpp}` (protobuf loader keeping only
wire-relevant flags), `Items::getModernClientId` + reverse lookup fed by
`data/items/modern_client_ids.tsv` (generated by
`harness/build_modern_ids.py`, stale rows pruned at load), and
`data/items/appearances.dat` (canary's 15.25-compatible file) for
validation.

### Phase C — enter world with a real client (commits `0a38c61`…`810cc43`)
**Why:** the whole point. **Ground truth the real client taught us:**
- Modern clients open the game connection with a plaintext
  `"<worldName>\n"` line before any framed traffic. `Connection` now
  consumes it (`skipWorldNameByte`).
- Every enter-game writer was ported to the 15.25 layout, gated per
  profile: login block 0x17 (no bug-report byte, exiva byte), stats 0xA0
  (u32 hp/mana, u64 exp, magic level moved out, mana shield), skills 0xA1
  (u16 quads, concoctions byte, the 14.10+ character-skill-stats tail,
  15.00+ mantra), basic data 0x9F (u16 spell ids + magic-shield byte),
  player state 0xA2 (u64 + counter byte), creature 0x6A (summon master
  ids, icon list + icon byte, vocation byte, inspection byte, no speech
  bubble/helpers, mount colors), magic/distance effects 0x83 (typed loop,
  u16 ids), tile description (no environment-effect u16), open container
  0x6E (search icon, filter block, moveable/holding), `sendItems` 0xF5
  (15.00+ packed-varint counts).
- All item wire writes funnel through `ProtocolGame::addItem/addItemId`
  so modern connections get mapped client ids plus appearance-driven
  extras; `NetworkMessage::addItem` stays legacy-only.
- Two bugs only the real client could catch: a missing creature-icon byte
  (one byte desynced the whole map stream) and u16 inventory counts where
  15.25 reads a packed varint.

### Style pass (commit `235111f`)
**Why:** the strict rule above. **What:** `EffectLoopCode` enum replaced
raw loop bytes, `CommonCode`/`SpecialCode` replaced marker literals,
`usesModernLayout()` replaced repeated generation checks, function-local
usings removed. Wire-identical — all gates re-ran green afterward.

### Live-play fixes (commits `fddac15`, `67ceef9`)
**Why:** found by actually playing. **What:**
- Walk desync: modern speed writes now use the same half-scale as legacy —
  the speed-formula constants sent at login are calibrated for it, and
  mehah feeds the received value straight into the formula. Verified by a
  16-step scripted walk ending at the exact position the server persists.
- Talk misalignment: 12.81+ clients read a statement-suffix byte after the
  speaker name; all four 0xAA writers now send it.
- GM boss crash: BlackTek's extended creature types (guild/party summons,
  `CREATURETYPE_BOSS = 7`) collapse onto the 0-5 the modern wire knows —
  bosses go out as monsters — in `AddCreature` and `sendCreatureType`.

### New 15.25 items (commits `b110abc`, `0fc1f7a`)
**Why:** ~20k items exist in the 15.25 client that the 10.98-era server
never had. **What:** `harness/build_new_items.py` reads `appearances.dat`,
finds every item appearance with no server item, and generates
`data/items/items_1525.toml` (20,805 items, server ids 30000–50804) plus
mapping rows. Gameplay attributes for 5,749 of them (weapons, armor,
tools) join in from canary's community-maintained `items.xml` — same
appearance-id key space — filtered to the `ItemParseAttributesMap`
vocabulary, with canary names/articles/plurals. The rest are decorations
that only need name + sprite. Regenerating is idempotent; a newer
appearances file just gets re-run through the same command.

## Verification, every change

Four gates, re-run after every landing: the 10-test golden suite, the
scripted legacy 10.98 walk, the scripted modern 15.25 walk, and a real
mehah 15.25 client driven by an auto-login harness (in the client folder,
not this repo) through login → world render → walk → GM actions, checked
for zero parse errors. Desync checks compare the client's reported
position against the server's persisted one.
